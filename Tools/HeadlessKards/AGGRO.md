# 日德快攻：脚本卡包与本地联机测试

当前规则版本：`subset-v0.4-aggro1`。Rust执行对局与效果，C#执行fyserver网络协议，Lua仅在构建时导出卡包。对局无需Lua VM；C#卡牌SDK也能构造相同IR。

## 已实现

`../CardExamples/aggro.lua`包含用户提供卡组的21种卡、特鲁克总部，以及突袭和爱知D3A两种衍生卡，共24个定义。完整39张牌保留原数量。

支持指定目标、飞机射程、同排战斗机保护、轰炸机反击规则、烟幕、奋战、钉住、攻击力光环、阵营/邻接查询、部署与攻击后触发、友军死亡触发、回合触发、免费入场、指定随机抽牌、延迟弃牌、生成卡牌和原生生成ID。

卡牌效果是IR数据，Rust中没有按这21种卡的ID分支执行效果。新增机制仍需要先扩展Rust原语，不能把任意脚本自动翻译成新规则。

几个关键顺序：轰炸突袭保存原始邻接列表后伤害主目标；信浓号先保存场上单位总数，每次伤害后重新选择随机目标；无所畏惧先选目标再生成爱知，伤害读取生成后的实际攻击力；海上补给运输登记两次全局换回合后弃牌；电信联队处理同批次死亡的其他友军。

## 随机与检查点

`reference`保留固定kards-sim xoroshiro128+契约。`client`使用独立UE5.6 FRandomStream，按Flora审计的包装在选卡前执行1至10次额外消耗。网络导入使用match_id初始化客户端流；不会重新洗牌或推测服务器洗牌流。

检查点包含随机seed与消耗数、每张卡的位置、当前回合生成序号、增益、钉住与烟幕状态，以及延迟效果。回放同时校验卡包指纹和随机配置。生成ID为`turn * 1000 + 当前回合生成计数`。

## 构建与测试

在restored根目录：

```powershell
pwsh -File Tools/HeadlessCore/Build.ps1
pwsh -File Tools/HeadlessCore/Test.ps1
pwsh -File Tools/HeadlessKards/Test-AggroServer.ps1
```

已验证：29项Rust语义测试；旧六卡规则11,284次差分；C#/Lua示例3,652项检查；日德卡包25种开局、1,578条规则行动、3,181项网络/回放检查。最后一项测试在独立`127.0.0.1:19145`的真实fyserver上完成双机器人对战：81条规则行动，双方最终状态相同，两份回放通过。报告在`artifacts/aggro-test-report.json`与`artifacts/aggro-server-report.json`。

隔离测试脚本仅启动并关闭自己的19145服务，不修改1145服务；测试卡组和账号写入隔离服务自己的数据库。

## 与用户的原版客户端联调

确保本地fyserver已在HTTP 1145启动，然后运行：

```powershell
pwsh -File Tools/HeadlessKards/Start-AggroBot.ps1
```

机器人自动登录专用账号`headless_lcorp_aggro`并准备日德卡组，进入对战码`LCORP`。用户使用原来的卡组代码：

```text
%%31|5C5x6B6y7xhHlfm6rk;3f3Q5X6EfRlknI;4p6x7e7l;5Z
```

`bot-aggro.json`中的卡组是fyserver专用格式，添加了正文分隔和明确总部后缀，避免服务端将后缀当成卡牌。不要用此专用字符串替换用户的原版导入代码。

机器人在发送后等待服务器回显才执行，不重试结果不明的POST。遇到不支持卡牌、非空sub_actions、错误游标或总部校验差异会停止并留下日志。

## 验证边界

尚未完成真人原版客户端的一局验证。两个机器人一致只证明实现自身的确定性与服务器协议链路，不证明与原版规则完全一致。仍需实机核对随机候选数组顺序、回合触发器与延迟弃牌之间的顺序、伤害/死亡事件细节、位置编号及首回合抽牌策略。当前网络配置要求local_subactions=true和空sub_actions。AI仍是简单启发式，重点是规则与同步，不代表成熟的快攻策略。

仅支持该卡池；对手换牌后预检会拒绝未支持卡牌。脚本新卡如果需要原版客户端显示和执行，还必须另外提供一致的游戏资产。
